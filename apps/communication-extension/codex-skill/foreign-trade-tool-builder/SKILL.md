# 外贸工具复用开发

把个人外贸工具母版中的领域逻辑和质量经验复用于新的客户项目，同时保持每个产品的品牌、数据、授权和发布边界独立。

- 不使用旧公司发布包、公司名称、公司 Logo、公司账号、专属接口或压缩构建代码作为新产品源码。
- 外贸母版是个人项目的唯一真实版本。客户项目必须建立独立仓库，不在母版中混入客户身份、凭据或私有数据。

定义外贸产品或功能优先级时，先读取用户真实调研记录 [../../docs/CUSTOMER_RESEARCH.md](../../docs/CUSTOMER_RESEARCH.md)。需要了解母版中哪些部分可直接复用时，读取 [references/reuse-map.md](references/reuse-map.md)。准备交付或升级时，读取 [references/delivery-gates.md](references/delivery-gates.md)。

## 先做复用判断

先确定用户真正要交付的形态、运行平台和一个主要客户场景。只有平台、品牌或数据边界会改变实现时才追问。

- Chrome/Edge 沟通侧边栏：以外贸工具母版创建独立下游，优先复用场景识别、回复生成、客户数据迁移和构建检查。
- Rust/Tauri 桌面软件：只有用户明确要桌面产品时才考虑 Harness。默认复用工程原则；要复制或实例化归档中的专有文件时，先确认现有授权明确覆盖这个下游和用途，再遵守归档仓库自己的初始化入口与许可。
- 手机 App、PWA、Obsidian 或其他宿主：不硬套 Chrome 或 Rust/Tauri 工程。复用外贸业务模型与交付门禁，按目标技术栈重建宿主层。
- 只需写一封邮件或润色话术：直接完成内容任务，不创建软件项目。

## 客户项目最小闭环

1. 用一句话定义客户要完成的工作和可观察成功标准。默认先判断客户要解决的是已有询盘开发、主动寻找公开线索，还是人脉信任与介绍；不要把“英文回复”默认当成最高价值需求。
2. 第一版只保留一个完整使用路径和至多三个核心功能。已有询盘类工具优先验证“询盘进入 → 背调证据 → 客户分级 → 下一步开发动作”；纯沟通工具才使用“客户消息 → 阶段判断 → 可编辑回复 → 客户/历史留存”。
3. 把稳定业务规则放在可测试的 core；浏览器、桌面或移动界面只处理输入、展示和宿主能力。
4. 默认本地优先。联网 AI 必须由使用者主动开启、自带接口，并清楚显示会发送哪些内容、发送到哪里。
5. 客户资料需要版本化数据结构、升级迁移、导出和恢复；密钥不得进入导出、日志、安装包或 Git。
6. 为每个客户使用独立名称、仓库、版本和安装包。未经授权不使用第三方品牌，也不把一个客户的数据或配置复制给另一个客户。

## 实施和交付

- 新建客户项目时从干净母版或必要模块开始，不复制母版的 `.git`、`dist`、`release`、真实数据或凭据。
- 保留能证明行为的单元测试，并增加该客户真实主路径的回归测试。
- 发布前生成真实可安装产物，核对产物内版本、权限、品牌和配置，再做至少一次目标宿主安装验收。
- 记录 SHA-256、支持的平台、未验证项、升级/回退办法和客户可理解的安装说明。
- 不把源码编译通过、开发预览或 CI 绿色表述为客户环境已经验收。

完成时报告：复用了哪些模块或原则、客户专属变化、真实验证、安装包位置、版本、剩余风险，以及是否使用了专有 Harness 文件。
