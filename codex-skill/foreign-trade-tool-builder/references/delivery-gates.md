# 客户软件交付门禁

这些门禁吸收桌面 Harness 中可跨技术栈复用的经验，但不代表可以复制其专有源码。

## 开工前

- 明确一个主要用户、一个真实场景、目标宿主和验收动作。
- 分开记录已验证事实、客户要求、合理推断和待验证假设。
- 确认产品身份和素材授权；不得默认沿用母版或其他客户品牌。
- 先检查目标仓库和目录，保护已有修改，不覆盖客户数据。

## 实现中

- 业务规则与宿主界面分开，稳定规则有非空测试。
- 权限、联网、文件读写和自动操作按最小范围设计。
- 所有外部请求有超时、可理解错误和失败关闭；不静默降级成误导性成功。
- 数据结构有 `schemaVersion` 或等价版本，并覆盖旧数据迁移。
- 默认值不制造真实业务承诺；价格、交期、认证、付款和物流事实由人确认。
- 机密不写入源码、示例、测试、日志、导出和构建产物。

## 构建前

- 从唯一版本事实源读取版本，源码、清单、界面和安装包保持一致。
- 运行相关测试、语法检查、品牌扫描、密钥扫描和权限检查。
- 构建目录由脚本确定性生成，不把旧文件混进新版本。
- 检查工作树，区分产品源码和本地生成物。

## 交付前

- 对真实 ZIP、安装器或扩展目录重新读取清单，而不是只检查源码。
- 解压或安装测试，跑通客户主路径并确认数据重启后仍存在。
- 覆盖升级一次，确认旧数据可迁移；准备导出备份或回退办法。
- 记录安装包文件名、版本、SHA-256、构建提交和实际验证平台。
- 给客户一页可执行安装说明，并写清联网、费用、数据去向和人工审核责任。

## 结论用语

- 测试通过：只说明自动测试覆盖的行为。
- 构建成功：只说明产物成功生成并通过静态检查。
- 安装验收通过：必须真实安装并跑过主要路径。
- 跨平台可用：每个平台都要有证据；未执行的平台标记为未验证。
- 可商业交付：还需要明确支持范围、更新承诺、退款/故障边界和客户授权，不由技术检查自动得出。
