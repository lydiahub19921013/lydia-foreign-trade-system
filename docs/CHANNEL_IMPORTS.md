# 询盘渠道导入

## 使用方式

可视化工作台中先选择“自动 / Lydia 标准表”“阿里巴巴”或“中国制造网”，再选择 CSV。文件只在当前浏览器读取，系统先打开“导入前核对”，不会立即替换当前空间的询盘。

核对窗口逐列显示：

1. 原文件表头；
2. 最多两个本机样例值；
3. 系统建议的 Lydia 字段；
4. 已识别、不会导入或同一字段有多列等状态。

用户可以把陌生列人工映射到 Lydia 字段，也可以选择“忽略此列”。只有点击“确认映射并导入”后，客户记录才写入当前空间；取消或按 Esc 不改变已有数据。确认结果会保存为 `lydia-csv-import-audit`，只包含列名、目标字段、核对时间、数量和告警，不保存弹窗样例值或被忽略列的单元格内容。

命令行仍使用固定别名映射：

```bash
npm run qualify -- ./询盘.csv --channel alibaba --output ./Lydia-客户分级.json
npm run qualify -- ./询盘.csv --channel made-in-china --output ./Lydia-客户分级.json
```

## 当前识别字段

系统会把常见中英文字段统一为以下 Lydia 字段：

| Lydia 字段 | 常见输入示例 |
|---|---|
| 来源编号 | Inquiry ID、RFQ ID、询盘编号、询盘链接 |
| 企业 | Company Name、Buyer Company、公司名称、买家公司 |
| 联系人 | Buyer Name、Contact Name、买家姓名、联系人 |
| 地区 | Country/Region、Market、国家/地区、市场 |
| 询盘 | Inquiry Content、Message、询盘内容、留言 |
| 产品 | Product Name、Inquiry Title、产品名称、询盘标题 |
| 数量 | Order Quantity、Purchase Quantity、采购数量 |
| 联系方式 | Email、Business Email、WhatsApp、Phone、工作邮箱、联系电话 |

## 重要边界

这些是兼容性建议，不是对两个平台当前导出格式的完整承诺。平台可能更改字段，不同账号和地区也可能不同。第一次导入真实文件时，必须在核对窗口检查所有有值列，并抽查至少 5 行的公司名、联系人、原始询盘、产品、数量和来源编号；错列时在确认前修改映射，并把真实表头脱敏后补进回归测试。

系统会明确提示未识别列、多个原列映射到同一 Lydia 字段、行宽异常，以及缺少来源编号、询盘/产品、企业身份或联系人资料的记录。多个原列映射到同一字段时，每行优先使用靠左的非空值。空白/重复表头、未闭合引号、没有数据行或没有任何可用业务字段时禁止导入。

样例值会显示在本机核对窗口中，但不进入导入核对记录。窗口不会判断样例内容是否含个人信息；真实客户文件仍不得提交到 Git 或公共聊天。

原始联系方式默认是 `candidate`。只有保留验证来源并明确标记为 `verified`，才会按已验证联系方式计分。

从 CSV 导入且有对应 Evidence 的官网、登记编号、工厂信息、邮箱、WhatsApp 和电话会记录字段来源。以后驳回这条证据时，系统只撤回仍未被人工修改的对应字段。旧 JSON 没有字段来源时仍可导入，但为了避免误删，系统不会猜测哪个字段应该自动撤回。
