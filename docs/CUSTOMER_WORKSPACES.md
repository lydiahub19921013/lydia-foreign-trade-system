# 本机客户空间

## 解决什么问题

Lydia 可能同时为不同外贸客户处理询盘、公开候选和信任路径。把所有资料放在一个浏览器快照中，即使没有上传，也会在切换客户时产生串数据、误导出和误清除的风险。v0.13 为每个客户建立独立的本机客户空间，让当前页面只加载、修改和导出一个客户的数据。

## 日常使用

1. 第一次打开会看到“我的客户 1”。如果这是已有数据迁移后的空间，先把它重命名为对应客户或项目。
2. 接到另一个客户时点击“新建客户空间”，使用能明确区分客户和项目的名称。
3. 顶部始终显示当前客户空间；导入文件、研究企业、记录活动和信任路径前先核对名称。
4. 切换客户时，工作台先等待当前空间完成保存，再把目标空间设为当前并重新载入。
5. 每次重要批次仍导出 JSON。导出文件名和顶层 `workspace` 都包含客户空间名称、编号和导出时间。

## 防串客户门禁

- 每个空间使用不同的 IndexedDB 快照键；A 空间不会读取 B 空间的 Lead、Evidence、公开候选、研究表单或关系路径。
- 带 `lydia-workspace-reference` 标记的 JSON，只有空间编号相同或空间名称相同时才能导入。两者都不一致会停止，并提示先切换或建立同名空间。
- CSV 和没有 Lydia 空间标记的旧 JSON 无法自动判断归属；导入前必须人工核对顶部当前客户名称。
- 清空只删除当前空间的快照并保留空间；删除空间会移除该空间及其本机快照，至少保留一个空间。
- v0.12 的旧 `current` 快照在首次启动 v0.13 时迁入“我的客户 1”，成功写入空间索引后才删除旧键。

## 安全边界

客户空间是单人、本机使用的数据分区，不是云端 tenant：

- 没有登录、角色权限、服务端隔离、跨设备同步或远程恢复；
- IndexedDB 未由 Lydia 额外加密，同一电脑账户和浏览器资料的访问者仍可能读取；
- 同时打开两个页面编辑同一客户空间时，后保存的完整快照可能覆盖前一个页面，当前应一次只编辑一个页面；
- 浏览器站点数据被清理、资料损坏或容量不足时，空间快照仍可能丢失；
- 客户空间名称本身也可能包含客户身份，不应在共享电脑使用真实名称。

因此，客户空间降低日常误操作风险，但不能代替受控 JSON 备份、设备权限和客户数据处理约定。如果未来做云端多人产品，必须另行设计用户身份、服务端 tenant 键、逐请求授权、加密、审计日志、备份恢复和越权测试。
