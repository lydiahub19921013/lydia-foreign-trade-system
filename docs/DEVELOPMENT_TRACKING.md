# 客户开发记录与结果回测

## 解决什么问题

分级只能决定“今天先投入谁”，不能证明高分客户更容易成交。Lydia 在询盘首次进入工作台时冻结当时的等级和分数，之后分别记录真实发生的联系、回复、报价、样品、订单、成交或流失。这样才能用历史结果检查分级规则，而不是用事后结果反过来美化最初判断。

## 使用流程

1. 导入询盘后，系统为每条 Lead 保存 `qualificationBaseline`，包含导入时等级、分数和时间。
2. 在客户卡片点击“记录开发进展”，只选择已经发生的事实；草稿、搜索摘要和预期不能记成客户动作。
3. 可以同时填写下一步和截止时间。下一步会作为独立待办保存，完成后原计划与完成时间都保留。
4. 阶段由仍然有效的活动推导：尚未开发 → 已联系 → 已回复 → 已报价 → 已寄样 → 已收到订单 → 已成交/已流失。
5. 误记的活动使用“撤回”。系统追加一条带原因的撤回事件，不删除原记录；阶段和统计按撤回后的有效事件重新计算。
6. 已成交或已流失客户如要继续跟进，先记录“重新进入开发”，不能悄悄覆盖原来的结果。
7. 导出 Lydia JSON，`development.events`、冻结基线和 `developmentSummary` 会一起保留；再次导入后可继续记录。
8. 工作台会把这些记录保存到当前客户空间，刷新或切换回来后恢复；这解决本机临时丢失，不代替跨浏览器或长期 JSON 备份。

## 事件与边界

可记录的业务事件包括：已联系、收到回复、已报价、已寄样、收到订单、成交、流失、重新开发、备注、安排下一步和完成跟进。金额和币种为可选事实字段，不参与当前客户分级。

- `doNotContact`、受限市场或已归入主账户的次记录不能新增外联或跟进待办；收到的入站回复仍可以作为事实保存。
- 流失、重新开发、普通备注和撤回必须填写原因，避免空白状态变更。
- 下一步内容和截止时间必须同时存在，截止时间不能早于记录时间。
- 完成待办必须引用一条仍未完成的计划，不能凭空制造“已完成”。
- 事件最多保留 500 条；每个客户使用独立客户空间。当前版本面向单人、本地、几十到几百条线索，不是带账号权限的多人 CRM 数据库。

## 统计怎么读

工作台按冻结的 A/B/C/D/HOLD 基线显示已联系、已回复、已报价、已寄样和成交的数量与比例。分母是该基线等级进入系统的全部独立账户，不只统计“愿意回复的客户”；已经人工确认归入主账户的次记录保留历史，但不重复进入分母。

样本不足时百分比没有稳定意义。至少用 20–50 条脱敏历史询盘补录真实结果，并同时检查：

- A/B 是否比 C/D 有更高回复、报价、样品和成交率；
- 高分未成交主要卡在价格、时机、产品匹配、信任还是长期无回复；
- 低分成交是否暴露了被现有规则遗漏的关键证据；
- 重复客户和 HOLD 是否被错误计入外联投入。

在完成真实回测前，界面中的比例只是样本描述，不能宣传为成交预测、行业基准或因果证明。
