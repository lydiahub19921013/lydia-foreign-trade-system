# 重复客户与主账户

## 解决什么问题

同一家海外客户可能从阿里巴巴、中国制造网、邮件或 CRM 多次进入系统。系统先根据渠道编号、企业登记号、企业域名、已验证工作邮箱，以及“公司名＋国家”生成重复候选，但这些信号都不能代替人工判断。

## Lydia 的处理方式

1. **确认为同一客户**：必须从两条记录中人工选择一个主账户并填写原因。另一条记录只增加 `duplicateOf` 关系并进入 HOLD；原始询盘、联系人、证据和备注全部保留，不自动覆盖到主账户。
2. **确认不是同一客户**：保存判断原因并关闭该组提示。适合集团子公司、共用域名、平台店铺或名称相似但法定主体不同的情况。
3. **重新判断**：撤销上一次决定。若域名、登记号等匹配证据仍存在，候选会重新出现。

每次决定都追加到两个 Lead 的 `duplicateReviews`，记录双方 ID、决定、主账户、时间、原因、当时的匹配强度和触发理由。schema 3 及以后版本的 JSON 导出和再次导入会保留这些历史。

## 为什么不直接“合并删除”

销售需要知道每次询盘从哪里来、客户分别问过什么，也可能在第一次判断后发现主体并不相同。直接拼字段会制造来源不明、覆盖人工资料和无法撤销的问题。因此 v0.10 的“合并”是建立可追溯的主账户关系，不是把两行资料破坏性压成一行。

次账户仍可贡献域名、登记号和已验证邮箱等指纹；如果它以后与第三条询盘匹配，系统会把候选归到现有主账户继续让人复核。

## 使用建议

- 相同企业登记号、相同渠道编号通常是强信号，但仍要检查是否为误导入或编号复用。
- 共用企业域名不一定是同一采购主体；集团、代理、经销商和平台店铺必须补看法定实体。
- 公司名和国家相同只是弱提示，不应仅凭名称确认。
- 在 20–50 条脱敏历史询盘完成回测前，不根据感觉调整阈值，也不宣传为自动客户归并。
