# 证据复核与字段回滚

## 为什么需要

官网、询盘导出和第三方登记记录都可能过期、错配或被重新解释。只记录“加入过什么”不够；系统还必须知道某个字段由哪条证据填入，并在发现错误时安全撤回。

## 三种人工动作

- **驳回**：保留原证据和原因，但停止把它用于分级、已验证邮箱重复判断和字段填充。
- **恢复**：保留驳回历史；仅当原字段仍为空或仍等于该证据原填充值时恢复，不覆盖人工修改。
- **修订**：更新证据内容或来源，记录修改前后值、原因和时间；只有仍由该证据管理的字段随之更新。

每次操作必须填写至少 3 个字的原因。Evidence 原有的 `candidate`、`inconclusive` 或 `verified` 状态与人工决定分开保存；“人工接受”不等于把候选升级为已验证。

## 字段来源

Lead schema 3 及以后版本延续 schema 2 引入的 `fieldOrigins`，记录：

- 字段路径，例如 `contact.email`；
- 对应 Evidence ID；
- 系统当时填入的值与时间；
- 该来源是否仍在管理字段，以及何时、为何停止。

驳回时只有“客户当前值仍等于系统原填充值”的字段会被清空。如果用户后来手工改过，系统保留人工值并结束自动管理。旧版 Lead 没有 `fieldOrigins` 时仍可复核证据，但不会猜测并清除字段。

## 沟通插件同步

外贸开发插件可读取 schema 3 及以后版本，并记录上次由 Lydia 导入的客户字段。重新导入分级文件时：

1. 字段仍等于上次 Lydia 导入值：允许更新或清空；
2. 字段已被用户在插件中修改：保留人工值并停止由 Lydia 管理；
3. 旧版客户没有管理记录：已有非空值默认视为人工资料，不自动覆盖或删除。

这保证工作台中的证据撤回可以传播到沟通环节，同时不会用自动同步覆盖销售人员的人工判断。
