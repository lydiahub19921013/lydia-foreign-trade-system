# Lydia 外贸系统 v0.10.0 验收

验收日期：2026-09-08  
环境：macOS 26.5.2、Node.js v22.23.0、Codex 本机浏览器

## 已通过

- 系统自动测试 91 项通过，覆盖同一客户、不同客户、重新判断、主账户必选、原因必填、链式关系阻止、次账户指纹归集和 JSON 往返。
- 外贸开发插件自动测试 24 项通过；v0.3.0 安装包继续通过可重复构建验证，SHA-256 为 `5893d2e26f4e2c33574b04badb949df6e8a124d67a92729c8ec3b1b07e0c3799`。
- 149 个文本文件完成禁用品牌和常见密钥扫描；Lydia Skill 校验通过。
- 浏览器用 4 条虚构询盘显示 1 组相同域名候选，匹配提示强度 95%，没有自动合并。
- 人工选择 `Northstar Demo Imports` 为主账户并填写原因后，另一条询盘进入 HOLD，同时继续显示原始询盘内容和主账户关系。
- “重新判断”会撤销主账户关系，匹配证据仍在时候选重新出现；“不是同一客户”会关闭提示并保留审计。
- 页面在桌面宽度下完成可视检查，候选、操作按钮、主账户状态和客户卡片没有明显遮挡或溢出。
- 浏览器导出的 schema 3 JSON 包含 4 条原记录、1 条已处理决定、两个 Lead 的复核事件和次账户 `duplicateOf`；导入外贸开发插件后次账户仍为 HOLD，原询盘内容保留。
- 上述浏览器 QA 只使用 `example` 虚构数据；本轮新导出文件已移到废纸篓，未提交仓库。
- Dedupe、Splink 和 GoldenMatch 的固定提交、MIT 许可证、用途、复制范围和数据去向已记录；本地许可证副本与上游原文一致。

## 尚未通过，不能扩大表述

- 匹配提示强度是固定规则的候选优先级，不是同一法定实体的概率保证。
- 没有真实渠道导出和 20–50 条历史询盘，不能声称阈值、误报率或漏报率已经校准。
- v0.10 不自动拼接两个 Lead 的字段；“合并”只表示建立主账户关系并停止重复开发。
- 当前控制接口没有替浏览器文件选择器完成自动回传，因此没有声称浏览器文件导入界面已自动回归；核心 JSON 往返和插件导入已验证。
- 没有在 Chrome 中人工执行从旧版插件原位升级到 v0.3.0，不能声称客户升级安装已验证。

因此当前结论是“重复客户可以安全建立、撤销和审计主账户关系”，不是“系统已自动完成企业实体解析”。
