# Lydia 外贸系统 v0.11.0 验收

验收日期：2026-09-08  
环境：macOS 26.5.2、Node.js v22.23.0、Codex 本机浏览器

## 已通过

- 系统自动测试 106 项通过，覆盖基线冻结、阶段推导、真实里程碑、待办完成、逾期计数、成交/流失、重新开发、带原因撤回、HOLD 门禁、重复账户分母排除、异常导入和 schema 4 往返。
- 外贸开发插件自动测试 24 项通过；v0.3.0 安装包继续通过可重复构建，SHA-256 为 `5893d2e26f4e2c33574b04badb949df6e8a124d67a92729c8ec3b1b07e0c3799`。
- 158 个文本文件完成禁用品牌和常见密钥扫描；`git diff --check` 与新增 JavaScript 语法检查通过。
- Atomic CRM 与 Krayin CRM 的固定提交、MIT 许可证、用途、复制范围和数据去向已记录；本地许可证文本与固定上游版本逐字节一致。
- 浏览器用 4 条虚构询盘冻结 4 条初始等级，并将一个 B 类客户推进为“已联系 → 已回复 → 已报价”；开发分保持 71，基线没有被后续结果改写。
- 同一虚构客户完成旧待办后能安排新待办；总览同步显示 1 条已联系、1 条已回复、1 条已报价和 1 个开放待办。
- HOLD 虚构客户尝试记录外联时被阻止并显示原因。
- 浏览器导出的 schema 4 JSON 保留 4 条原始询盘、4 条冻结基线和 6 条开发事件；`developmentSummary` 与界面一致。
- 上述 schema 4 浏览器导出成功导入外贸开发插件，客户等级和原始询盘内容保持不变。
- 页面在桌面宽度下完成视觉检查，等级筛选、开发筛选、统计卡片和转化表没有明显遮挡或溢出。
- 本轮浏览器 QA 只使用 `example` 虚构数据；没有向上游 CRM 或外部服务发送客户、联系人、金额或开发备注。

## 尚未通过，不能扩大表述

- 尚无 20–50 条脱敏历史询盘和真实后续结果，不能声称 A/B 比 C/D 转化更高，也不能把当前比例当成行业基准或成交概率。
- 浏览器中的活动撤回已由核心测试覆盖，但本轮没有自动操作原生 `prompt` 完成界面撤回回归。
- 当前工作台不会自动持久化；关闭或刷新前必须导出 JSON，长期使用体验仍需本地持久化方案。
- 当前没有从邮箱、WhatsApp 或平台自动读取活动，也不会自动发送消息。
- 浏览器文件选择器没有完成自动回传测试；核心 JSON 往返、浏览器导出和插件导入已经验证。
- 没有在 Chrome 中人工执行从旧版插件原位升级到 v0.3.0，不能声称客户升级安装已验证。

因此当前结论是“系统已经能记录并回看真实客户开发结果”，不是“系统已经证明评分能预测成交”。
