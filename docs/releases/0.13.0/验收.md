# Lydia 外贸系统 v0.13.0 验收

验收日期：2026-09-08  
环境：macOS 26.5.2、Node.js v22.23.0、Codex 本机浏览器

## 已通过

- 系统自动测试 112 项通过，新增覆盖空间索引净化、重复名称拒绝、导出标记和文件名、跨客户导入停止、旧单快照迁移、双空间保存隔离、按空间清空、切换、重命名和至少保留一个空间。
- 外贸开发插件自动测试 24 项通过；v0.3.0 安装包继续通过可重复构建，SHA-256 为 `5893d2e26f4e2c33574b04badb949df6e8a124d67a92729c8ec3b1b07e0c3799`。
- 170 个文本文件完成禁用品牌和常见密钥扫描；`git diff --check` 与 JavaScript 语法检查通过。
- 浏览器把首个空间重命名为“虚构客户 A · 水杯”，载入 4 条虚构询盘并完成自动保存。
- 新建并切换到“虚构客户 B · 家具”后页面为空，没有出现 A 的 4 条询盘；在 B 中载入 3 条虚构关系记录，得到 2 条候选路径。
- 切回 A 后恢复 4 条询盘且没有 B 的关系路径；再切回 B 后只恢复 2 条关系路径且没有 A 的客户面板。
- 在 B 中执行“清除当前客户数据”后，B 为空而 A 仍在空间列表；删除 B 后自动回到 A，4 条询盘继续完整恢复。
- 新建、切换、清空和删除对话框都显示明确客户名称和影响范围；只剩一个空间时删除按钮禁用。
- 每次刷新和空间切换后 Exa/官网联网授权都保持未勾选。
- 最终代码模块重新载入后，A 空间和 4 条询盘仍能恢复；桌面宽度视觉检查没有明显遮挡或溢出。
- 所有浏览器 QA 只使用保留域名和虚构名称，没有发送真实客户、联系人、关系或开发活动。

## 尚未通过，不能扩大表述

- 旧 v0.12 `current` 快照迁移和跨客户 JSON 导入门禁已通过模块测试，但本轮没有在独立真实 Chrome 资料中人工制造旧存储并完成迁移，也没有把真实下载文件重新上传做宿主级回归。
- 本轮验证的是同一 Codex 本机浏览器、同一 `http://127.0.0.1:4173` 来源，不代表所有 Chrome/Edge 资料、隐私模式或浏览器崩溃场景。
- 没有在真实配额耗尽时触发保存失败，也没有验证两个页面同时编辑同一空间的冲突合并；当前设计是后保存的完整快照可能覆盖先保存者。
- 本机客户空间没有应用层加密、登录、角色权限或服务端 tenant 授权，不能称为云端多租户、加密客户数据库或多人 CRM。
- 尚无 20–50 条脱敏历史询盘和真实结果，不能声称评分已经预测成交。
- 没有在 Chrome 中人工执行旧版插件到 v0.3.0 的原位升级。

因此当前结论是“Lydia 在同一本机浏览器中可以把不同客户的工作台快照分开保存、切换和清除”，不是“已经具备云端多租户或多人协同安全”。
