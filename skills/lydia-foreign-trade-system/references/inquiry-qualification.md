# 已有询盘分级

## 适用输入

阿里巴巴、中国制造网、展会、邮件、表格或人工记录中的已有询盘。优先请求脱敏 CSV/JSON；不得把真实客户数据提交到公共仓库。

## 流程

1. 保留渠道、原始询盘编号/链接和收到时间。
2. 识别企业、联系人、产品、数量、时间、预算和已发生的购买动作。
3. 只把有来源的官网、工商、工厂、工作邮箱等标为 verified。
4. 默认运行仓库的 `npm run workbench`，在本地网页选择渠道并导入；批处理可使用 `npm run qualify -- <file>`。
5. 人工抽查证据，输出 A/B/C/D/HOLD、理由、缺失证据和下一步。
6. 导出 Lydia 客户分级 JSON，在沟通插件“备份与恢复”中导入；选择客户后会载入原始询盘和下一步建议。
7. 进入沟通插件生成草稿，由用户确认后发送。
8. 发现已入档证据错误或过期时，在工作台填写原因并驳回、恢复或修订；确认字段回滚和分级变化后重新导出到沟通插件。

## 判断标准

- A：证据和需求都比较完整，有明确行动信号，优先人工开发。
- B：值得开发，但先补最影响判断的两项证据。
- C：先确认身份、需求或角色，再投入时间。
- D：当前信号弱，保留但不深度开发。
- HOLD：不联系、受限市场、重复或无法核查身份，先解决阻断项。

等级只表示开发优先级，不代表信用评级或成交预测。

驳回只撤回仍由该证据管理且未被人工修改的字段。旧记录没有字段来源时不自动猜测删除；人工拒绝的 Evidence 不再参与分级或已验证邮箱重复判断。
