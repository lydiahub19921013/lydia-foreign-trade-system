# 公开线索研究

## 目标

找到匹配目标市场的企业和业务联系人，并为每个结论建立来源证据；不是最大化抓取数量。

## 推荐顺序

1. 先定义产品、地区、应用场景、公司类型和目标角色。
2. 从公司官网、官方工商/行业目录、公开展会名单和搜索结果识别企业。
3. 将企业身份、网站、地址、经营/工厂信息分别记录来源和观察时间。
4. 联系方式分为 candidate、inconclusive、verified、rejected。
5. 至少使用公司官网/企业域名和另一个独立来源交叉核查重要联系人。
6. 输出“证据 + 不确定性 + 下一步”，不要输出无来源的联系方式清单。

## 外部工具

官网提取或邮箱验证只能作为 `integrations` 提供方。启用前核对目标网站条款、访问限制、许可证、费用和数据去向。任何 SMTP、catch-all 或搜索推断都可能误判。

主动公开候选搜索已接通：

- 在“主动找客户”填写产品、市场、买家类型和应用场景，先生成目标买家、明确需求、问题/替代、近期变化和行业渠道 5 个搜索方向。
- 使用者勾选确认后，可由本机 agent-reach 把选中的搜索词发送给 Exa；不要在搜索词中加入询盘正文、私人通讯录或联系人资料。
- Exa 不可用时，可导入 `lydia-public-prospects` JSON 或标准候选 CSV，文件仍只在浏览器处理。
- 搜索标题/摘要都是 `search-candidate`，最高 49 分；无公开来源、原文信号和原页人工核查，不得进入优先名单。
- 点“送去官网补证”，确认并读取原始公开页面后，才允许加入主动开发队列；它仍不是客户主动询盘。

工作台的 GLEIF 查询是已接通的企业身份核验来源：

- 运行 `npm run workbench`，主动输入企业法定名称，可选填司法辖区。
- 只把这两个字段发给 `api.gleif.org`，不发送询盘或联系人数据。
- `ISSUED` 且 `FULLY_CORROBORATED` 只代表该条 GLEIF 记录可以作为已核实身份信息。
- 有 LEI 不代表信用好、会付款或有采购意愿；没有结果也不代表企业不存在。
- 查询结果必须与官网、辖区、地址等人工比对后，再决定是否并入客户档案。

公开官网补证也已接通：

- 只接受使用者主动指定并确认公开/获授权的一张页面，不做搜索引擎或整站抓取。
- 拦截内网、异常端口、跨站跳转、非文本和超大页面。
- 页面公开邮箱、电话、WhatsApp、地址与工厂描述全部标记为 `candidate`。
- 人工确认后可以加入选定询盘；只填补空字段，不覆盖客户原资料。
- 公开联系入口不等于营销同意，不能据此自动发送消息。

候选邮箱功能用于“已有姓名＋企业域名”的补证：

- 英文名只在浏览器组合，DNS 只收到企业域名。
- 最多生成 10 个常见姓名/职能地址；命名规则、MX 和官网公开都不证明具体邮箱存在。
- `mail-domain` 可以核实域名邮件路由，但具体 `business-email` 仍为候选。
- 企业域名与询盘已有域名不一致时禁止保存。
- 不运行 SMTP、不发送测试邮件，也不自动触达。

## 禁止

不绕过登录/验证码，不批量抓取私人资料，不出售个人信息，不自动发送验证邮件或营销消息。
