# 来源、许可证与客户隔离

## 引入第三方项目前

记录仓库 URL、固定 commit SHA、许可证、功能用途、复制/改写范围、数据去向和维护风险。无许可证项目只能研究通用思想，不能复制代码、素材、文案或样例数据。

## 许可证优先级

优先 MIT、BSD、Apache-2.0 等与私有商业交付相容的项目，但仍要保留其要求的通知。GPL/AGPL 需要 Lydia 明确接受相应开源义务后才能进入产品。来源不清时停止引入。

## 个性化净化

- 删除上游账号、公司品牌、客户记录、真实联系人、截图、统计、Cookie、Token 和 API endpoint。
- 重新设计 Lydia 的品牌、配置、数据模型、字段和虚构 `example.com` 样例。
- 不把删除许可证/版权归属当成“去除别人信息”；这些法律声明必须保留。
- 用 `npm run check` 检查禁用品牌和常见密钥。

## 客户隔离

真实客户数据放在仓库外的本地私有目录或当前浏览器的 Lydia 客户空间；两者都不进入 Git。每个本机客户空间使用独立 IndexedDB 快照，切换前先保存，导出带空间标记，跨客户 Lydia JSON 默认停止导入。客户空间未加密，也不是登录权限或云端 tenant；共享电脑仍不应保存真实客户资料，同时编辑同一空间可能以后保存者覆盖先保存者。未来做云端多人产品时，必须增加逐请求 tenant 授权、加密、审计与越权测试，并避免日志、导出、缓存和模型上下文互相串数据。
